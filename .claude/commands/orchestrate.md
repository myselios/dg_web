# /orchestrate - Agent Teams Parallel Orchestration

당신은 병렬 태스크 오케스트레이터입니다. DAG(Directed Acyclic Graph) 기반으로 태스크 의존성을 분석하고, 웨이브 단위로 서브에이전트를 병렬 디스패치합니다.

---

## 개요

복수의 태스크를 의존성 순서에 따라 병렬로 실행합니다.
최대 동시 실행 에이전트 수는 3개이며, 웨이브(wave) 단위로 진행합니다.

---

## Step 1: 태스크 소스 로드

### 소스 우선순위

1. **인자로 전달된 경우:** `--plan <path>` 또는 `--tasks <json>`
2. **ai-auto 파이프라인 내:** `.ai-auto/plan.json`의 현재 웨이브
3. **수동 입력:** 사용자에게 태스크 목록 요청

### 태스크 구조 (필수 필드)

```json
{
  "tasks": [
    {
      "task_id": "T-001",
      "title": "태스크 제목",
      "description": "상세 설명",
      "files": ["src/target.py"],
      "depends_on": [],
      "complexity": "M",
      "test_files": ["tests/test_target.py"]
    }
  ]
}
```

---

## Step 2: DAG 구성 및 검증

### DAG 생성

1. 각 태스크를 노드로, `depends_on`을 간선으로 DAG 구성
2. **순환 의존성 검사:** 순환이 발견되면 즉시 중단하고 사용자에게 보고
3. **고아 의존성 검사:** `depends_on`에 존재하지 않는 task_id가 있으면 경고

### 위상 정렬 및 웨이브 계산

DAG를 위상 정렬하여 웨이브로 분할합니다.

```
Wave 1: [T-001, T-002, T-005]  ← 의존성 없는 태스크
Wave 2: [T-003, T-004]          ← Wave 1에 의존
Wave 3: [T-006]                  ← Wave 2에 의존
```

**웨이브 규칙:**
- 같은 웨이브 내 태스크는 서로 의존하지 않음
- 한 웨이브가 완전히 완료되어야 다음 웨이브 시작
- 각 웨이브 내에서 최대 3개 동시 실행

### 출력

```
[ORCHESTRATE] DAG 분석 완료
─────────────────────────
총 태스크: {N}개
웨이브: {N}개
최대 병렬도: {N} (cap: 3)

Wave 1: T-001, T-002, T-005
Wave 2: T-003 (← T-001), T-004 (← T-002)
Wave 3: T-006 (← T-003, T-004)
─────────────────────────
```

---

## Step 3: 웨이브 실행

### 웨이브 실행 프로세스

```
for each wave in waves:
    ├── 1. 실행할 태스크 선택 (최대 3개)
    ├── 2. 각 태스크에 대해 서브에이전트 디스패치
    │   ├── 에이전트 컨텍스트 준비
    │   ├── superpowers:dispatching-parallel-agents로 병렬 실행
    │   └── 결과 수집 대기
    ├── 3. 결과 검증
    │   ├── 성공: 완료 기록
    │   ├── 실패: 재시도 또는 에스컬레이션
    │   └── 파일 충돌 검사
    └── 4. 다음 웨이브로 진행
```

### 서브에이전트 디스패치

각 서브에이전트에게 전달할 컨텍스트:

```
[Agent Context for Task {task_id}]

## 태스크 정보
- ID: {task_id}
- 제목: {title}
- 설명: {description}
- 복잡도: {complexity}

## 수정 대상 파일
{files 목록}

## 관련 테스트
{test_files 목록}

## 의존 태스크 결과
{depends_on 태스크들의 완료된 코드 변경 요약}

## 코딩 규칙
- 불변성 패턴 사용 (뮤테이션 금지)
- 함수 50줄 이하
- 파일 800줄 이하
- AAA 패턴 테스트
- 에러 처리 필수

## 완료 조건
1. 구현 완료
2. 관련 테스트 PASS
3. 린트 PASS
```

### 동시 실행 제한

| 웨이브 내 태스크 수 | 동시 에이전트 | 실행 방식 |
|---------------------|---------------|-----------|
| 1-3 | 태스크 수 | 모두 병렬 |
| 4-6 | 3 | 2 배치로 나누어 실행 |
| 7+ | 3 | 3개씩 순차 배치 실행 |

---

## Step 4: 충돌 감지 및 해결

### 파일 충돌 감지

같은 웨이브에서 여러 에이전트가 동일 파일을 수정한 경우:

1. **충돌 감지:** 각 에이전트의 변경 파일 목록을 교차 비교
2. **자동 병합 시도:** 변경 위치가 다르면 자동 병합
3. **수동 해결:** 동일 위치 변경 시 사용자에게 보고

### 충돌 방지 전략

- 태스크 분배 시 동일 파일을 수정하는 태스크는 가능하면 다른 웨이브에 배치
- 공통 유틸리티 파일은 별도 태스크로 먼저 완료
- 인터페이스/타입 정의는 Wave 1에 배치

---

## Step 5: 진행 상황 추적

### 실시간 상태 표시

```
[ORCHESTRATE] Wave {W}/{total_waves} 실행 중
═══════════════════════════════════════════
Agent 1: T-001 "사용자 인증 구현" ............ [DONE]
Agent 2: T-002 "API 엔드포인트 추가" ......... [RUNNING] (3/5 loops)
Agent 3: T-005 "DB 스키마 생성" .............. [DONE]

전체 진행: ████████░░░░░░░░ 5/12 (42%)
═══════════════════════════════════════════
```

### 상태 파일 갱신

`.ai-auto/orchestrate-state.json`에 실시간 상태 저장:

```json
{
  "current_wave": 2,
  "total_waves": 3,
  "tasks": {
    "T-001": { "status": "completed", "agent": 1, "loops": 3 },
    "T-002": { "status": "in_progress", "agent": 2, "loops": 3 },
    "T-003": { "status": "pending", "agent": null, "loops": 0 }
  },
  "last_updated": "ISO-8601"
}
```

---

## Step 6: 실패 처리

### 태스크 실패 시

1. **재시도 (1회):** 동일 태스크를 다시 디스패치
2. **에러 분석:** 실패 원인이 의존성 문제인지 확인
3. **스킵 판단:** 실패한 태스크에 의존하는 후속 태스크도 스킵 처리
4. **보고:** 실패 태스크와 영향받는 태스크 목록을 사용자에게 보고

### 부분 실패 시 계속 진행

```
실패한 태스크: T-003
영향받는 태스크: T-006 (depends_on: T-003)

→ T-006을 스킵하고 나머지 태스크 계속 진행
→ 최종 보고서에 스킵된 태스크 명시
```

## 다른 명령과의 연동

- `/ai-auto` Phase 3에서 자동 호출
- `/next-task`의 추천 결과를 태스크 소스로 사용 가능
- 각 에이전트 완료 후 `/verify-loop`로 검증 가능

---

## 금지 사항

- 동시 에이전트 수 3개 초과 금지
- 순환 의존성이 있는 DAG 실행 금지
- 웨이브를 건너뛰어 실행 금지 (이전 웨이브 완료 필수)
- 실패한 태스크의 결과를 후속 태스크에 전달하지 않음
- 충돌 해결 없이 동일 파일 변경 사항을 덮어쓰지 않음
