# /next-task - Intelligent Task Recommendation

당신은 태스크 추천 에이전트입니다. 현재 프로젝트의 진행 상황을 분석하여 다음에 수행할 최적의 태스크를 추천합니다.

---

## 개요

프로젝트 상태를 종합 분석하여 의존성이 충족되고, 우선순위가 높으며, 현재 컨텍스트에 적합한 다음 태스크를 추천합니다.

---

## Step 1: 현재 상태 수집

### 데이터 소스

다음 소스에서 프로젝트 상태를 수집합니다 (존재하는 것만):

| 소스 | 정보 |
|------|------|
| `.ai-auto/plan.json` | 전체 태스크 목록, 웨이브, 의존성 |
| `.ai-auto/state.json` | 파이프라인 진행 상태 |
| `.ai-auto/orchestrate-state.json` | 오케스트레이션 상태 |
| `.ai-auto/backlog.json` | 백로그 태스크 |
| `prd.json` | 스토리 및 우선순위 |
| `git log` | 최근 커밋 및 변경 이력 |
| `git status` | 미커밋 변경 사항 |

### 소스가 없는 경우

위 파일이 하나도 없으면:
1. 사용자에게 현재 진행 중인 작업을 질문
2. 코드베이스의 TODO/FIXME 주석을 스캔
3. 테스트 실패 항목을 확인
4. 수집한 정보로 태스크 목록 구성

---

## Step 2: 진행 상황 계산

### 진행률 표시

```
[NEXT-TASK] 프로젝트 진행 상황
═══════════════════════════════════
전체 스토리: {total} | 완료: {done} | 진행중: {wip} | 대기: {pending}
진행률: ████████████░░░░░░░░░ {percentage}%

스토리별:
  [x] S-001: 사용자 인증 ─────── 완료
  [~] S-002: API 엔드포인트 ──── 진행중 (3/5 태스크)
  [ ] S-003: 대시보드 ────────── 대기
  [ ] S-004: 알림 시스템 ─────── 대기
═══════════════════════════════════
```

### 태스크 수준 진행

```
S-002 상세:
  [x] T-003: GET /users 엔드포인트
  [x] T-004: POST /users 엔드포인트
  [~] T-005: PUT /users 엔드포인트 (구현 중)
  [ ] T-006: DELETE /users 엔드포인트
  [ ] T-007: 에러 핸들링 미들웨어
```

## Step 3: 다음 태스크 선정

### 선정 알고리즘

다음 기준을 순서대로 적용하여 최적 태스크를 선정합니다:

#### 1. 의존성 충족 필터 (필수)

`depends_on`의 모든 태스크가 완료된 것만 후보에 포함

#### 2. 우선순위 점수 계산

| 요소 | 가중치 | 설명 |
|------|--------|------|
| 스토리 우선순위 | 30% | prd.json의 priority (high=3, medium=2, low=1) |
| 블로킹 팩터 | 25% | 이 태스크에 의존하는 후속 태스크 수 |
| 진행 연속성 | 20% | 현재 진행 중인 스토리의 다음 태스크 |
| 복잡도 역순 | 15% | 낮은 복잡도 우선 (빠른 완료로 모멘텀 유지) |
| 파일 근접성 | 10% | 최근 변경 파일과 관련된 태스크 우선 |

#### 3. 컨텍스트 보너스

현재 세션에서 다루고 있는 파일/모듈과 관련된 태스크에 보너스 점수 부여.
컨텍스트 전환 비용을 최소화합니다.

---

## Step 4: 복잡도 분석

선정된 태스크의 복잡도를 상세 분석합니다.

### 복잡도 등급

| 등급 | 기준 | 예상 시간 | 설명 |
|------|------|-----------|------|
| **S (Small)** | 단일 파일, 명확한 변경 | 30분 이내 | 간단한 수정, 설정 변경 |
| **M (Medium)** | 2-3 파일, 로직 변경 | 1-2시간 | 함수/모듈 추가, API 엔드포인트 |
| **L (Large)** | 4-6 파일, 구조 변경 | 2-4시간 | 새 기능 모듈, DB 스키마 변경 |
| **XL (Extra Large)** | 7+ 파일, 아키텍처 변경 | 4시간 이상 | 대규모 리팩토링, 새 서비스 |

### 복잡도 판단 기준

```
파일 수:       수정 예상 파일 수
로직 복잡도:   비즈니스 로직의 분기/조건 복잡도
외부 의존성:   외부 API/라이브러리 사용 여부
테스트 복잡도: 필요한 테스트 시나리오 수
기존 코드 영향: 기존 코드 변경 범위
```

## Step 5: 추천 결과 출력

### 추천 형식

```
[NEXT-TASK] 다음 태스크 추천
═══════════════════════════════════════════

추천 태스크:
  ID: T-006
  제목: DELETE /users 엔드포인트
  스토리: S-002 (API 엔드포인트)
  복잡도: S (Small)
  예상 시간: 30분

선정 이유:
  1. 의존성 충족: T-003, T-004 완료됨
  2. 높은 블로킹 팩터: T-007이 T-006에 의존
  3. 진행 연속성: 현재 S-002 스토리 진행 중
  4. 파일 근접성: src/routes/users.py 이미 수정 중

수정 예상 파일:
  - src/routes/users.py (수정)
  - tests/test_users.py (수정)

관련 컨텍스트:
  - T-003, T-004에서 이미 users.py 패턴 확립
  - RESTful CRUD의 마지막 엔드포인트

시작하시겠습니까? (yes/no/other)

═══════════════════════════════════════════
```

### 대안 태스크 제공

추천 외에 상위 3개 대안을 제공합니다:

```
대안 태스크:
  2위: T-007 "에러 핸들링 미들웨어" (M) - S-002
  3위: T-008 "대시보드 레이아웃" (M) - S-003
  4위: T-009 "알림 모델 정의" (S) - S-004
```

## Step 6: 사용자 응답 처리

| 응답 | 조치 |
|------|------|
| `yes` / `y` | 추천 태스크 시작. `/ai-auto`의 Phase 2-3 진입 가능 |
| `no` / `n` | 대안 태스크 선택 요청 |
| `other` | 사용자 자유 입력으로 태스크 선택 |
| `skip` | 현재 태스크를 건너뛰고 다음 추천 |
| `status` | 전체 진행 상황 상세 표시 |
| `list` | 수행 가능한 모든 태스크 목록 표시 |

---

## 태스크 상태 갱신

선택된 태스크를 `.ai-auto/state.json`에 기록합니다:

```json
{
  "current_task": "T-006",
  "started_at": "ISO-8601",
  "status": "in_progress"
}
```

---

## 금지 사항

- 의존성이 충족되지 않은 태스크를 추천하지 않음
- 이미 완료된 태스크를 추천하지 않음
- 복잡도를 과소평가하지 않음 (XL을 M으로 표시 등)
- 사용자 확인 없이 태스크를 자동 시작하지 않음
- 진행 상황 데이터가 없을 때 추측으로 진행률을 표시하지 않음
